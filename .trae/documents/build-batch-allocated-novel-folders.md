# 按 Sub-agent 分配表重建小说文件夹结构

> 计划日期：2026-06-21
> 范围：12 份 batch 速查表 + 9 子类 + 77 部小说 → 6 batch × 73 SA × N novels
> 不动：原 9 子类文件夹（01_战队特摄 ~ 09_女性向）、2 份源文档、6 份深度阅读笔记、77 部源小说、73 sub-agent 分配

---

## 一、Why（为什么做）

当前 77 部小说按 9 个**子类**组织（01_战队特摄 ~ 09_女性向），但 73 sub-agent 是按 6 个**批量**分配的（按 SA-XX-X 跨子类取书）。Sub-agent 启动时必须：
1. 读速查表找到自己的 SA-XX-X
2. 速查表给出完整路径（跨多个子类的多个小说）
3. 自己拼接路径去读小说

**问题**：
- Sub-agent 需要跨 9 子类目录找书（认知负担）
- 超限本（如 裆能战记系列 28 章）被拆给 4 个 SA，**子段范围**需要 sub-agent 自己用 `第 N 章` 推断
- 同一部小说在原目录是 1 份，被分给 4 个 SA 时没有物理隔离

**优化**：在 `pixiv小说/` 下新建 `1_战队特摄/` ~ `6_同人+女性向/` 6 个 batch 目录，按分配表**硬拷贝**章节文件（不全复制，按章节范围只拷贝分配的章节）：

```
pixiv小说/
  01_战队特摄/      ← 原 9 子类（保持不动）
  02_勇者魔物奇幻/
  ...
  1_战队特摄/       ← NEW batch 1
    SA-01-A/
      裆能战记系列_子段1/   ← 仅 1-14 章（按速查表范围）
    SA-01-B/
      裆能战记系列_子段2/   ← 仅 15-23 章
    ...
  2_勇者魔物奇幻/   ← NEW batch 2
    SA-02-A/
      《豪想和你在一起》_子段5/   ← 仅 57-69 章
    ...
```

#### C-1. 全本（无超限拆分）

#### C-2. 子段（超限本拆分）
如 SA-01-A 的《裆能战记系列》子段 1/4（第 1-14 章）：
```
SA-01-A/

子段命名规则：`<novel_name>_子段<N>/<M>/`
- 例：`_子段1/`、`_子段2/`、`_子段3/`、`_子段4/`
- N = 当前子段号（1/4 中 N=1, 2/4 中 N=2, 依此类推）
- M = 总子段数（如 4）

### D. 拷贝章节文件（硬拷贝，按章节范围）

| 类型 | 章节范围 | 拷贝文件数 |
|---|---|---|
| 全本 | 1-N (N=总章数) | N 个 .txt |
| 子段 | 第 a-b 章 | (b - a + 1) 个 .txt |

只拷贝 `.txt` 文件，**不拷贝**：
- `作品信息.txt`（元数据）
- `pixiv小说.zip`（打包文件）
- 子目录内其他元数据文件

文件名**保持原样**（如 `#1 【裆能战记1】荣誉之战.txt`）。

从 12 份 batch 速查表 §X "批量 N" 段提取分配表：

PATTERN_NOVEL = r"\d+ \| (.+?)(?:（子段 (\d+)/(\d+)）)? \| .+/([^/]+)/`（(?:子段 \d+/\d+：)?第 (\d+)-(\d+) 章"

def copy_assets(assignment_map):
    for batch_id, sas in assignment_map.items():
        batch_folder = NOVEL_BASE / f"{batch_id}_{get_batch_name(batch_id)}"
        batch_folder.mkdir(exist_ok=True)
        for sa_id, novels in sas.items():
            sa_folder = batch_folder / sa_id
            for novel in novels:
                novel_name, seg_num, seg_total, ch_start, ch_end = novel
                if seg_num:
                    novel_folder = sa_folder / f"{novel_name}_子段{seg_num}/"
                else:

                novel_folder.mkdir(parents=True, exist_ok=True)
                
                src_folder = find_source_folder(novel_name, ch_start, ch_end)
                for ch in range(ch_start, ch_end + 1):
                    src_file = find_chapter_file(src_folder, ch)
                    if src_file:
                        shutil.copy2(src_file, novel_folder / src_file.name)
```

### 关键工具函数

#### `find_source_folder(novel_name, ch_start, ch_end)`
在 9 子类（01_战队特摄 ~ 09_女性向）中找到包含 `novel_name` 的目录。

#### `find_chapter_file(src_folder, ch_num)`
在源目录中找到匹配 `#{ch_num} *.txt` 的文件。

**匹配规则**：
- 优先匹配完全匹配（如 `#1 【裆能战记1】荣誉之战.txt`）
- 次优匹配前缀（`#1 *.txt` 但 `1` 在前）
- 处理前导零（如 `#01` vs `#1`）
- 处理中文数字（如 `第一章` vs `#1`）

## 八、Risk & Mitigation

| 风险 | 影响 | 缓解 |
|---|---|---|
| 12 速查表解析失败（行格式不一致） | 任务中断 | 写 1 份样本解析器后逐 batch 测试，失败即停止 |
| 原目录章节文件命名不规范（如中文数字 vs 阿拉伯数字） | 拷贝错位 | 在 `find_chapter_file` 用宽松正则（`#N` 或 `第N章` 都接受） |
| 源目录缺失某些章节（如"印第安部落之歌前传"缺 #1/#7/#10-14） | 部分文件未拷贝 | 解析时记录缺失文件，给出报告；不中断其他文件拷贝 |
| 超限本 4x 复制占用磁盘 | 200-300MB 冗余 | 用户已选硬拷贝；可加 README 说明可清理 |
| 同名 novel 在 9 子类出现重名 | 错拷 | 用速查表"完整路径"列里的子类别前缀精确定位 |
| 文件名特殊字符（`【】`、`《》`、`"…"`） | 路径编码问题 | 用 Path 对象 + `os.fsencode`/`fsdecode` 兜底 |
| 任务中途崩溃（如 SA-04 解析失败） | 部分已建 | 写一个"续传"机制：每完成 1 个 SA 就保存进度 |

## 十一、关键决策（Key Decisions）

| # | 决策 | 说明 |
|---|---|---|
| D1 | **硬拷贝**（非软链接）| 用户选择；优点：sub-agent 看到真文件 |
| D2 | **不全复制**，**只复制分配的章节** | 用户明确要求 "不全复制，根据分配表来分章节" |
| D3 | **按 novel 名分子目录** | 用户选择 "按 novel 名分"；优点：同 novel 不同 SA 的章节物理隔离 |
| D4 | **超限本加 `_子段N/` 后缀** | 推荐选项 1：明确表示子段号，避免冲突 |
| D5 | **保持原文件名**（如 `#1 *.txt`）| 不重命名，sub-agent 与速查表描述一致 |
| D6 | **不复制元数据**（作品信息.txt, *.zip）| 节省空间，元数据对子代理无意义 |
| D7 | **Batch 目录直接放在 `pixiv小说/` 下**（与 9 子类并列）| 与速查表"完整路径"列保持一致风格 |
| D8 | **不做硬链接**（D1 已选）| 即便磁盘可省，sub-agent 看到软链接可能困惑 |
| D9 | **不写 README**（除非 Step 6 用户要求）| 用户没要求 |
| D10 | **不修改原小说文件名**（如 `#1` vs `第1章`）| 速查表范围按阿拉伯数字解析，文件名保持原样 |
