# Sub-agent 分配优化 Spec

## Why
当前 `sub-agent 小说速查表` 存在严重的体积失衡问题：36 个 sub-agent 中有 18 个分配的小说总大小超过 500KB（实测单次 Read 硬上限），其中 SA-02-F 达 1721.4KB、SA-04+05-F 达 1862.9KB。这会导致 sub-agent 在 Read 源小说时被上下文截断、笔记残缺。需按章节大小重新切分超限本并重平衡分配。

## What Changes
- **重命名文件**：`v2-阶段4.1-sub-agent小说速查表_2026-06-20.md` → `sub-agent分配速查表.md`
- **拆分超限本**（>500KB 的单部小说）：按章节大小均匀拆给多个 sub-agent
- **重平衡分配**：每个 sub-agent 负责的"总大小 ≤ 500KB"硬约束
- **更新章节号映射**：拆分后写入段落（4.X / 5.X）编号需重新编排
- **保留 6 份笔记文件的写入目标路径不变**

## Impact
- Affected specs: `expand_xiaoyingxiong_skill_v2`
- Affected code: 1 个 markdown 文件（速查表）
- Affected sub-agents: 由 36 个扩为约 60-70 个（拆分会增加 sub-agent 数）

## 硬约束
1. **每 sub-agent 总大小 ≤ 500KB**（实测单次 Read 硬上限）
2. **单部小说 > 500KB 时**必须按章节拆给多个 sub-agent，**章节按字节大小均分**（不是按章数）
3. **同子类（4.1-4.X）可被多 agent 协作**：拆分后同一笔记段可由 2+ agent 写入不同子段（如 4.1a、4.1b）
4. **总字符下限按比例**继承原方案（9-10 分 ≥ 15k，30+ 章 ≥ 40k，75+ 章 ≥ 80k）
5. **写入笔记文件路径不变**：仍为 6 份 `pixiv_深度阅读笔记_*.md`

## 拆分算法
- 单部小说 > 500KB → 计算章节文件大小（按文件数或估算）→ 按字节大小**贪心装箱**：
  - 目标：每段 ≤ 500KB
  - 段内：顺序章节（保持叙事连贯）
  - 段数：⌈总大小/500KB⌉，向上取整
- 拆分后每段作为"独立分配单元"参与 sub-agent 装箱
- 装箱时同一笔记文件下尽量保持子类连贯
