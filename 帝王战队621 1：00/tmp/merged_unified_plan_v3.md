4. **不跳过通读**：所有规划均为通读而设。
5. **每本输出 5 必含元素 + 实际读 X/Y (X%) 标注。**

## 四、输入输出规范（详细版）

### 4.1 输入规范
- 单 sub-agent 输入文件大小 ≤ 500KB（实测硬上限）。
- 超限时按自然卷/ storyline 拆段，每段 ≤ 500KB。
- 每段路径明确标注 start_line / end_line。

### 4.2 输出规范
每部作品必须包含：
1. **实际读 X/Y (X%)**：X = 实际读取章节数，Y = 总章节数。
2. **作品定位**：一句话核心卖点 + XP 命中。
3. **关键章节**：具体章号 + 关键情节。
4. **完整套路**：≥ 3-5 条本小说特有套路。
5. **关键场景**：≥ 5 个具体场景（含章节号）。
6. **角色弧光**：主角 + 关键配角 + 反派。
7. **v2 SKILL 升级建议**：1-3 条对应 references 扩展。

### 4.3 字符预算（柔性下限 + 上限不封顶）

| 权重 | 字符下限 | 说明 |
|---|---|---|
| 9-10 分 | ≥ 15,000 | 完整 5 必含 |
| 7-8 分 | ≥ 6,000 | 5 必含（可略简） |
| 5-6 分 | ≥ 3,000 | 5 必含（紧凑） |
| 1-4 分 | ≥ 1,500 | 4 必含 |
| 75+ 章超长篇 | 可超 80,000 | 按卷分段 |
| 30+ 章长篇 | 可超 40,000 | 按卷分段 |

## 五、子代理分配规则（已结合实测优化）

### 5.1 分配原则
- 单本 ≤ 500KB：1 个 sub-agent 直接处理。
- 单本 > 500KB：按 500KB/段拆分，每段 1 个 sub-agent。
- 小书按 4+2+4+5+1+2+2 式自然邻接打包，总负载 ≤ 500KB。

### 5.2 分批策略
- 6 个批次**依次启动**（批次间串行）。
- 每个批次内 sub-agent **同时启动**（最大并行）。
- 批次完成后主代理沉淀，再启动下一批次。

### 5.3 写入策略
- 直接写入正式 4.X/5.X 段，不写临时文件。
- 同笔记的多个 sub-agent 写入时机**错开**（串行）。
- 每批次完成后主代理校验 X% 实际读率。

## 七、Execution Order（Step-by-Step）

### Step 0：主代理前置检查（每次 sub-agent 启动前必做）
1. Read 速查表（统一 1 次/批次）。
2. Read 对应批次的深度阅读笔记。
3. 将两者内容嵌入 sub-agent `message` 字段。

### Step 1-6：批次执行
- 每批次读取对应速查表小节。
- 每批次内 sub-agent 同时启动（并行）。
- 每本 ≤ 500KB 直接读；> 500KB 先切分再读。
- 读完即写 4.X/5.X 段，不积压。

### Step 7：阶段 4.2 合并（6 个 merge sub-agent）
- 读取该批次所有 sub-agent 输出。
- 合并到正式 6 份深度阅读笔记。
- 更新 TOC + 锚点。

### Step 8：阶段 4.3 验证
- 验证 6 份深度阅读笔记的实际读 X/Y (X%)。
- 验证 101 部小说全部覆盖。
- 验证 TOC 锚点有效。
- 更新 `pixiv_记忆文档.md` 第 5 次沉淀。

## 十、Risk & Mitigation

| 风险 | 数据支撑 | 缓解 |
|---|---|---|
| 大文件溢出 | 600KB 失败，500KB 通过 | 硬性 500KB 上限 + 自动切分 |
| 子代理上下文丢失 | 800KB NIAH 中 50% 位置失败 | 分段读取 + 段末自检 |
| 2 sub-agent 写冲突 | 同份笔记并行写入 | 同笔记串行，错开写入时机 |
| 跨本合并幻觉 | 多本聚合时角色混淆 | 每本独立 4.X/5.X 段，不混写 |
