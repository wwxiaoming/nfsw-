> **用途**：sub-agent 启动时**单文件速查**，无需再翻源文档。

> **来源**：
> - `tmp/execution_packets.md`（101 部小说 + 章节 + 总大小清单）
> - 各小说目录的实际章节文件字节数（贪心装箱）

## 1. sub-agent 启动 3 步走
1. **找到自己的 ID**（如 `SA-01-A`）→ 跳到对应小节

3. **Write 笔记对应段落**（段落编号 4.X / 5.X）→ 写入目标见各批量开头"写入目标"段

## 3. 字符预算（柔性下限 + 上限不封顶）

**核心原则**：下限保质量，上限不封顶。

| 调整后权重 | 字符下限 | 5 必含版本 |
|---:|---|---|
| 9-10 分（高分） | **≥ 15,000** 字符 | 完整 5 必含 + 推荐元素 |
| 7-8 分（中分） | **≥ 6,000** 字符 | 5 必含（可略简） |
| 5-6 分（中低分） | **≥ 3,000** 字符 | 5 必含（紧凑） |
| 1-4 分（低分） | **≥ 1,500** 字符 | 4 必含 |
| 75+ 章超长篇单本 | **可超过 80,000** 字符 | 完整 5 必含 + 章节详细表 |
| 30+ 章长篇 | **可超过 40,000** 字符 | 完整 5 必含 |

**章节数基准公式**（推荐起算点）：
- **每章 800-1,500 字符**（保证每章都有实质内容）
- 例：24 章 = 19,200-36,000 字符（9-10 分区间）
- 例：10 章 = 8,000-15,000 字符（9-10 分区间）

> ⚠ sub-agent 可**根据实际内容自由突破上限**——写得越详细越好。**硬性下限是必须达到的**。

## 4. 最少必含项（不可省略 4 项 + 推荐元素池）

### 4.1 最少必含 4 项
1. **作品定位**（核心卖点 + XP 命中）
2. **关键章节**（至少 3 个章节的具体情节）
3. **核心套路**（至少 3 条本小说特有的套路）
4. **v2 SKILL 升级建议**（至少 1 条对应 `references` 扩展）

### 4.2 推荐元素池（13 项，可自由选用、扩展、重组）
- 作品定位 / 关键章节 / 完整套路 / 关键场景 / 角色弧光
- 世界观设定 / 写作技法 / v2 SKILL 升级建议
- 可复用元素 / 戏剧冲突结构 / 情绪曲线
- 对白风格 / 跨作品对比

> 高分作品（9-10 分）可扩展到 7-10 个元素；中低分灵活精简。

## X+1. 大文件读取提示（避免上下文溢出）

对超长篇（>30 章）或大体积文件（实测 >300KB）使用 `Read` 工具的 `offset` + `limit` 分段读取：

```python
# 示例：分 3 段读《豪想和你在一起》76 章（约 450KB）
Read(file_path=path, limit=2000, offset=0)   # 第 1 段
Read(file_path=path, limit=2000, offset=2000) # 第 2 段
Read(file_path=path, limit=2000, offset=4000) # 第 3 段
```

**本版硬约束**（替代原文档 §13 的 500KB 软上限）：
- **每 sub-agent 总大小 ≤ 500KB**：本速查表已按此硬约束装箱
- **单部 >500KB 的小说已预先拆段**：按章节大小贪心分给多个 sub-agent
- **子段内 ≤ 500KB**：直接 Read 全文即可，无需再分段
- **分段策略**（仅用于子段内仍有 > 500KB 章节文件）：
  - 75+ 章：3-4 段（按 500KB/段拆分）
  - 30-50 章：2-3 段
  - 10-30 章：1-2 段
  - <10 章：直接读全文
  - **硬上限**：单次读取 ≤ 500KB，超过必须拆分
